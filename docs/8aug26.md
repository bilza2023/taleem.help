ok ::: i learnt  big big big lessons in last 15 days or so (this phase) : 

1: when it comes to front end nothing moves faster than sveltekit (yes sveltekit not just svelte). any front end in ejs , static html etc is soo old that it will collapse the moment you need 1 new feature. SO for rest of my life front end = svelte. 

2: for all your front end code / libraries the best place is svelte/lib not npm as seperate packahes (as long as they speak the same language). no matter how big your eco system use same enums and keep the together.

3: when it comes to backend nothing beats simple node-express-prisma-sqlite no stack some close - you can have a server up in hours.   

4: The best server configuration is (keep http and db seperate) 1: seperate kernel (prisma + db + schema). this expose a simple crud like api . 2: create routes . this will give us a server which has just 2 stopping points  check route check kernek. 

i studies MVP , SMVP , objects bla bla --- nothing nothing simplified the server as this simple trick - split kernel and routes. done. 

5: Express: important point is scrap middle-ware completely : express debugging is 90% middle-ware -- and if you fix it for 1 it breaks for other route . the solution is every simple EACH route has its own checking methods -- there will be max 3-4 route files and totla 10-20 routes --- so no group middle-ware.

6: just like kernel+http seperation simplified server . seperating front end into svelte and backend in a simple json based api server simplified web-development as a whole. if the server is rendering files , html etc etc the old way --- this server will never be finally close and will remain in debugging state for ever.
